# Запуск воркеров (конвенции и лимиты)

> Операционный опыт 2026-11-05: 8 параллельных воркеров правили главы
> книги. Модели воркеров: `worker`/`reviewer` (см. также
> `research/04-agent-pipeline.md`).

## Лимит параллельности

- При запуске **8 воркеров одновременно** провайдер (zai/glm) отдал
  `429 code 1302` половине запусков на первом же запросе.
- Рабочая схема: **≤4 одновременных воркера**; упавшие ран-ы поднимать
  через `subagent {action:"resume"}` по одному на каждое завершение
  работающих (нативный wake) — повторных 429 не было.

## Изоляция записи

- Один воркер = один файл главы + свой служебный файл (`service-chNN.md`)
  + опционально свой `parked/` файл. Никаких общих файлов на запись —
  слияние service-файлов в `service-notes.md` делает оркестратор один раз
  в конце.
- Файлы «только чтение» для воркеров: корпус (`data/normalized/*.jsonl`,
  `knowledge/index/posts.jsonl`), глоссарий A1, `outline.md`, чужие главы.

## Промпты

- Общие правила выносить в файл-указатель, в задаче — только специфика
  главы (задачи получаются компактными). Осторожно: в 2026-11-05 общий
  файл лежал в `tmp/` (gitignored) и переживает сессию только в wiki;
  канонический дом правил — `research/book/drafts/_rules-for-workers.md`.
- Стиринг работает: доп-пункт можно доставить работающему ран-у через
  `subagent {action:"steer"}` (применено для цитаты #1569 в гл. 2).
- Воркеры сами прогоняли `npm run typecheck`/`npm test` — безвредно для
  docs-правок и ловит случайные правки кода.
