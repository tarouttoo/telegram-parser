## Как меряют биржу: стресс-тесты, маркет-дата и зонд

**Стресс-тесты: «понасиловать апишики».** Получив ММ-программу на спот: «решил понасиловать апишики и погонять стресс-тесты на споте и на фьючах,
чтобы понять максимум возможностей и максимум при длительной работе и вообще выяснить как быть самым быстрым на текущих условиях для всех мм (кроме
биржевых понятное дело - у них прямой доступ к ядру биржи)» (grisha#124). Граница: «Мекс и Akamai уводят ip в ошибки после 50 запросов в секунду. А
после продолжительного такого спама Akamai вообще банит ip на срок от 5-15 минут до нескольких часов» (grisha#124).

**Первый прикид скорости: 28 мс на споте, 40 rps — потолок.** «Выше 40 заявок в секунду с одного ip нет никакого смысла гнать. Так как медиана
задержки плэйс = обработка на мексе + Akamai ~ 28мс на споте, и ~ 20-23мс кэнсел. И физически больше 40 в секунду без ошибок не вдуть» (grisha#126).
Фьючерсы: «на плэйс там лэтенси ~ от 65 мс (биток, золото) и от 140мс (все остальные) и плюс 28мс (обработка мекс + Akamai) - как раз те пресловутые
искусственные задержки мекса»; «Кэнсел такой же как на споте ~ 20-23 мс» (grisha#126). Замер: aws-tokyo az4; полная анатомия пути — секция ниже.

**Маркет-дата как рамка замера.** «Маркет-дата - это такой ключик во все двери всех участников стакана - можно зайти и посмотреть чем они занимаются
и примерно прикинуть взглядом сколько они зарабатывают/теряют» (grisha#130); с ММ-программами на споте и фьючах можно «найти такие же, но еще пустые
двери для себя» под свой латенси и логику бота (grisha#130). Метод маркет-даты целиком — (→ гл. 11).

**Зонд: два измерителя в одном.** «2 в одном - и лидлаг-бот с предиктом (тоже готов) и мейкер-тестер тоже с предиктом»; «И этот зонд будет
исследовать уже все биржи» (grisha#145). Хранение маркет-даты — (→ гл. 11); прострелы как стратегия — (→ гл. 6); здесь зонд — инструмент измерения.

**Прогоны: четыре биржи за полчаса.** «Отдельные апишки на бинанс, байбит, битгет (через брокерку) и окх - субакк на личном акке» заняли «полчаса в
понедельник» вместе с вводом средств и ключей (grisha#143); итог первой ночи — (→ гл. 6). Предикт, слушающий биржи из весов прайс-дискавери, даёт
результаты «по ощутимому маленькому предсказыванию цены (0.5-1.5мс)»: «Но это больше к моей теме (хфт) применимо чем в прострелах» — и полезен «как
предикт и фильтр для других бирж, где событие (прыжок) еще не случилось» (grisha#143). Цикл замера: раз в 24 часа прогон всех стратегий по
маркет-дате → корректировка → новые настройки — (→ гл. 8).

## Анатомия постановки на MEXC: Akamai перед биржей и искусственная очередь

**Akamai — край перед биржей.** Любой запрос к MEXC из AWS Токио идёт через край Akamai: TCP до края ~2 мс, путь через край до шлюза биржи ~10 мс;
«Любой запрос к MEXC из AWS Токио туда-обратно идёт не меньше ~21 мс» (grisha#135). При ~200–250 запросах/с с одного IP — страница «Access Denied»,
затем несколько секунд 403 на всё: «В эти секунды не проходит и закрытие позиции» (grisha#135). После продолжительного спама — «Akamai вообще банит
ip на срок от 5-15 минут до нескольких часов» (grisha#124).

**Путь фьючерсной постановки: 143 мс по этапам.** Замер 26.10.2026, AWS Токио (ap-northeast-1, az4); все цифры от нуля — момента отправки — и не
суммируются (grisha#135):

| Момент от отправки | Что происходит | ID |
|---|---|---|
| 0 мс | отправили заявку | grisha#135 |
| ~12 мс | Akamai: TCP до края ~2 мс, путь через край до шлюза биржи ~10 | grisha#135 |
| 12 → ~120 мс | очередь приёма фьючерсных заявок, ~105–110 мс — «Это искусственная задержка: на споте этот же этап занимает ~3 мс» | grisha#135 |
| ~120–127 мс | заявка принята ядром фьючерсов, биржа ставит свою метку времени; матчинг — единицы мс | grisha#135 |
| ~140–143 мс | ответ дошёл до нас | grisha#135 |
| ~148–150 мс | заявка видна в публичном стакане, через 5–8 мс после ответа | grisha#135 |

**Спот идёт без очереди.** Заявка в ядре спота на 15-й мс с меткой биржи, ответ на 31-й, отмена 23 мс; 165 тысяч замеренных постановок, 14–16.10; от
Akamai до ядра ~3 мс против ~108 на фьючерсах (grisha#135). «Пустой запрос — 21 мс туда-обратно. Это дорога: Akamai в обе стороны плюс ответ шлюза,
без работы ядра» (grisha#135). Отмена фьючерсов — 26 мс, без искусственной задержки (grisha#135).

**Три странности сравнения спота с фьючерсами.** Отмена на споте (23 мс) быстрее отмены на фьючерсах (26–28) на 3–5 мс: фьючерсное ядро на снятии
делает больше работы, похоже, пересчитывает маржу позиции. Постановка на споте (31) медленнее отмены на споте (23) на 8 мс: поставить дороже, чем
снять — проверка баланса, риск-контроль, матчинг; снятие — просто удалить строку. Постановка на фьючерсах (143) медленнее постановки на споте (31)
на 110 мс — это уже не работа ядра, а очередь приёма перед ним; ни отмена, ни спот через такую очередь не идут (grisha#135).

**Каналы различаются на единицы миллисекунд.** Постановка, медиана/p90/p99: API 143/162/204 против веб-канала 152/171/205 — API быстрее на 9 мс;
отмена 26/41/70 против 33/46/64 — на 7 мс; «Вид заявки (лимит, пост-онли, IOC, FOK) и сторона на задержку не влияют» (grisha#135).

**Исключение — группа BTC на ММ-счётах.** BTC, BCH, BNB, PAXG на ММ-счетах принимались за 52–65 мс от нуля: очередь ~40 мс вместо ~110, ответ на
62–65-й, в стакане на 70-й; на розничном счёте 26.10 те же фьючерсы — как все, 145–156 мс: «Быстрый приём — свойство счёта, а не монеты»
(grisha#135).

**Вывод источника и связки.** «Снаружи быстрее ~120 мс до ядра не попасть: 12 мс Akamai плюс ~108 мс очереди приёма, одинаково для розницы и для
ММ-программы» — статус ММ на скорость не влияет (grisha#139). Различение: здесь измерена очередь ПРИЁМА заявок; очередь РАЗДАЧИ маркет-даты — другой
механизм (→ гл. 9). Почему очередь стоит ~110 мс и как устроен путь команды внутри биржи — (→ гл. 9, кейс kucoin). Колокация мимо очереди
существует, но не для всех — (→ секция «„Быстрый чел“» ниже); колокация как институт — (→ гл. 9).

## Вход в биржу можно выбрать: версии и режимы API

**Тезис: входов несколько, и они не равны.** У биржи обычно несколько входов — версии API, режимы счёта, каналы (API против сайта) — и разница между
ними измерима: миллисекунды, лимиты, комиссии (grisha#110, grisha#135).

**Сломанная версия стоит месяцев.** Кейс секции 1: поломка версии API стоила месяцев ожидания и месяца игнора поддержки, откат на старую починил всё
сразу (alko-trading#729).

**Смена входа меняет экономику сразу.** «На кукухе я сидел на classic api и у меня cancel был 4.5 ms avg»; UNIFIED API «оказалось быстрее 2.5+ раза»
— «Теперь cancel занимает 1.6 ms» (grisha#110). Дальше экономика: без фильтрации toxic flow −3 bps на объёме, с фильтрацией +3, после смены входа с
фильтрацией — +10 (grisha#110; механика и цена фильтрации — → гл. 7).

**Режимы счёта — тоже вход.** Канал API против сайта даёт разные комиссии (→ секция «Комиссии» ниже), статус ММ — лимиты в 15 раз выше при той же
скорости (→ секции «Рейт-лимиты» и «Цена статуса» ниже) (grisha#135, grisha#139).

**Контракт соединений — часть входа.** Heartbeat, ping-pong, keep-alive: цифры и приёмы — (→ гл. 9).

**Асимметрия каналов бывает и ордерной.** RPI-ордер по API разместить можно, тейкнуть по API нельзя — RPI-сага целиком — (→ гл. 3).
