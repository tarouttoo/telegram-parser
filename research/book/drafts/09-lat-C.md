## Внутри биржи: куда утекает миллисекунда

Путь taker-команды (alko-trading#1662, по kucoin HFT handbook; «у всех остальных схема примерно такая
же, просто со своими нюансами»): your AWS server > AWS ELB > API gateway > risk engine > match engine >
push gateway. Таблица «шаг → что можно не угадать» (всё — alko-trading#1662):

| шаг | что можно не угадать |
|---|---|
| сервер → ELB | по AWS Fabric («в пределах aws сеть не ethernet»); ELB multi-AZ может свести и в соседнее физическое здание: зоны — «физические датацентры, между ними десятки километров и 0.5-1 ms latency» |
| API gateway | «распаковывает ваш TLS, проверяет вашу авторизацию»; их несколько и в разных AZ — «тоже можно на неудачный попасть» |
| risk engine | «кусочек базы данных которая отвечает за ваши ордера и балансы»: проверяет бабло, лочит его, шлёт в matching; закреплён один раз по userid («по последней цифре вашего юзера») — попадёте на «загруженном тупящем серваке, где сосед сыпет taker orders» |
| matching | FIFO place/cancel, метчит, отдаёт результат в push gw; shared или dedicated: «BTC_USDT это dedicacted, а GOVNO2_USDT это shared» — сосед активничает, ваш инструмент «затупливает» |
| push gateway | FIFO результатов, JSON по websocket в public/private streams; «тоже не один, тоже можно неудачно попасть» |

Статус меняет путь через risk engine (alko-trading#1662): UTA проверяет риск «за O(1)», portfolio
margin pro у binance (с vip7) «почти полностью исключает проверку risk'a» — «у кого vip7 или выше -
могут размещать лимитки БЫСТРЕЕ остальных, даже если они дуют их в API позже».

Маршрут зависит от команды (alko-trading#1662): «cancel проходит через risk engine, а cancel all -
нет, она попадает сразу в matching» — «cancel all по инструменту - быстрее точечного cancel by id»;
у binance раньше stop loss ставился в конец очереди досрочно.

Каждый шаг пути — место, где можно не угадать (alko-trading#1662). ELB-детали со стороны подписчика —
(→ секция «Доставка маркет-даты» выше); анатомия API как таковая (эндпоинты, замеры MEXC) — (→ гл. 12).

## E2E как бизнес-метрика

E2E (event-to-event) — время от fill на одной бирже до fill на другой: «на kucoin мы словили fill и
побежали откупаться - через сколько мы зафилимся на binance»; считается «по event time бирж (c
поправкой на ms cutoff если она есть)» (alko-trading#1712). «И все это хули-факинг-трейдинг дрочево -
ради уменьшения E2E».

Метрика не открытие alko: «года четыре назад» о ней рассказывали впустую, а недавно он «подсмотрел ее
у одного хорошего HFTшника» — и впервые увидел «число напротив каждой сделки» вместо отдельных fill
time, network path и place (alko-trading#1712).

Главное наблюдение (alko-trading#1712): «для каждой биржи и каждого инструмента есть некий порог E2E,
до которого стратежка пашет в плюс, а после которого резко минус»:

| связка | порог E2E |
|---|---|
| kucoin spot via binance | <3.2 ms — «Больше 3.2 ms - меня разносят» |
| kucoin futures via binance | <2 ms |
| whitebit spot / futures via binance | <69 / 68 ms |
| okx via binance, HK-эпоха | <19 ms («пока он был в hk») |

Оговорка: «цифры применимы к моей стратегии и механизму выставления ордеров, у вас могут быть другие
требования по latency». Вывод: «E2E это как-бы бизнес-метрика HFT-инфраструктуры» (alko-trading#1712).

Ориентир grisha «2мс ядро-ядро» (grisha#146) ложится между порогами alko: совпадает с kucoin futures
(<2 ms), в 30+ раз строже whitebit (<68–69 ms) — «2 мс» не универсальное число, а порог ликвидной
связки. Цитата и кейс Rust vs Python — (→ гл. 8); открытый вопрос гл. 8 об авторстве ориентира закрыт.

Latency решает раньше фильтра (alko-trading#1779): classic API кукухи — cancel 4.5 ms, токсик-фильтр
отделял +3 bps от −3 bps; UNIFIED API («быстрее 2.5+ раза», cancel 1.6 ms) — сразу 10 bps: «latency
решает, и если она херовая - то никакая фильтрация токсика сильно не поможет». Toxic-фильтр —
(→ гл. 7); анатомия API — (→ гл. 12).

Открытый вопрос: E2E-порог okx токийской эпохи не назван — переезд состоялся, доставка «стабильнее,
но дольше на 1 мс ахаха» (alko-trading#1675; сюжет — в «Рынке линков» ниже); в «Открытые вопросы главы».

## Дорога в Токио: биржа сама решает, насколько вы быстры

Отправная точка (alko-trading#176): «Рынок можно обыграть только арбитражем или скоростью» — «или ты
находишь арбитраж, или ты быстрее принимаешь решения (счет уже пошел на миллисекунды), или тебе конец».

Эдж — техника (alko-trading#226): «"секретное оружие" это не знание некой секретной торговой системы,
а техническое или финансовое преимущество» — видеть цену на 1 ms раньше, нулевые комиссии, 50
проверяемых стратегий в день против одной в месяц.

Первый замер масштаба (alko-trading#81): роут-движок решает за 10 ms — 16 000 000 маршрутов за 0.01 сек
(1.6 миллиарда в секунду); «заняло это переписывание 1.5 года каждый день».

Биржа стратифицирует участников напрямую (alko-trading#514): лента трейдов — опоздание 100 ms против
11 ms у market maker program («в 10 раз быстрее блиать»); стакан — 120 против 11 ms; вброс ордера —
900 против 50 ms («в 18 раз быстрее»).

Стакан везде присылается раньше ленты трейдов «на 10-50-100ms» — «Это делается специально»: при
обратном порядке «можно просто шикарно озолотиться» (alko-trading#279). Без vip binance задерживает
и aggTrades — «пока у тебя нет vip level, то что там, что там будет 100ms»: «надо просто подарить
бинансу 25 BNB и попросить менеджера» (alko-trading#480).

Переезд hetzner→Токио (alko-trading#518, alko-trading#519, alko-trading#520): данные 110→5 ms, трейды
binance 110–140→1.5 ms, вброс ордеров 900→50 ms. Uplink 10G в hetzner куплены «за кучуденег» — «А я
два года мудохался почему арбитраж сдувается».

Геометрия пары (alko-trading#537): binance в Токио, bybit в Сингапуре; сигнал 37 ms, ММ переставляет
цену «на 38й ms» — арбитражёру «надо толкаться в этой 1ms», «дальше будет еще быстрее», «Выиграет тот,
кто построит прямую оптику :)» — рынок линков в секции ниже.

Имя зоны ≠ дата-центр (alko-trading#934): одна и та же зона «1a» в разных aws-аккаунтах — разные
физические здания (apne1-az4 против apne1-az3): «когда говорят "binance находится в tokyo zone-1a" -
это блять вилами по воде!». Два года спустя alko ловит тот же топор сам: во Франкфурте настроил
сервера по имени зоны вместо фиксированного zone ID — «2 года торговал в плюс, имея повышенную latency
+0.8 ms всегда», хотя «я ЗНАЛ про этот прикол» (alko-trading#1666).

Почему все биржи в Токио (alko-trading#1739): почти все копируют стакан binance как true price
(справедливая цена) и хотят кратчайший маршрут «binance > ME > binance» — из Токио «максимум 3-4 ms»,
из HK «уже 40 ms (и это с дорогущими microwave линками по 20 000 баксов за 1 мегабит, в месяц)», и «за
эти 40 ms может поменяться все что угодно». Поэтому биржи вне Токио — «или большие спреды или большие
taker fee»: «Им надо как-то покрывать эту проблему». True price как термин — (→ гл. 7); кластеры 15
бирж и цифры задержек — (→ гл. 3).

## Рынок линков: прейскурант и субмарины

Прейскурант Токио↔Гонконг (alko-trading#1199; имена компаний alko не называет — при обращении «они
сразу просят подписать NDA»):

| канал | задержка в одну сторону | условия |
|---|---|---|
| интернет «как нибудь» | 54 ms | |
| aws backbone (vpc peering) | 52 ms | в обоих случаях оптика идёт по дну океана, «не заходя на материк» |
| ULL-провайдеры: оптика | 40 ms | канал сколько угодно: «хочешь гигабит - пожалуйста» |
| ULL-провайдеры: радиовышки | 38 ms | 5 мегабит, пакеты 60 байт, «канал не стабильный», «но в 90% времени он на 2 ms быстрее чисто оптики»; «от 35 000 евро в месяц» |
| китайцы: куски оптики по материку | 38 / 37 ms | «Ценники повыше, но не значительно» |
| submarine-оптика без выходов на берег | ещё −2 ms | «и канал супер стабильный» |
| LEO-спутники — теоретический предел | ~20 ms | «тучка прилетела, котик прилег и жопа твоему трейдингу» |

Радиовышки быстрее оптики физически: «скорость 300 000 км/с, а у оптики около 200 000 км/с»; оптика
не бывает непрерывно длиннее 5000 км — свет затухает, кабель «постоянно подходит к берегу» к
усилителям; «нарисовались ебанутые китайские ребята» — «они поставили подводные лодки, у них submarine
optics» (alko-trading#1199).

Лондон–Токио (alko-trading#938): 223 ms по aws против 132 ms у сети с «микс оптики и радиовышек» —
«это самая быстрая сеть в мире», но «в цене ПЯТЬ НОЛЕЙ :)».

Рекорды обновляются под тобой: «Только я купил сеть HK <=> TOKYO 20 ms», как китайцы выдали «premium
low latency of ~18.5ms» — arb-mm на okx «снова пошел лесом» (alko-trading#1362). Токио–Сингапур:
63.1 ms против типичных 65 (alko-trading#1398). Телеметрия показывает bybit быстрее 30 ms — «меня
разносят, а я не понимаю пока как именно»; кто продаёт такие линки — «Вызываю помощь зала»
(alko-trading#1497).

**OKX-сюжет: загадка и решение.** «Появились какие-то черти, которые успевают binance <=> okx за
19 ms», а на рынке есть линки только 19.5 ms (alko-trading#1247). Разгадка — colo okx (colocation)
(alko-trading#1306): не endpoint с public ip, а «transit router сразу с private ip» внутри alibaba
cloud Hong-Kong («Latency 150 us (0.15 ms)»); private-трафик гонится AWS Direct Connect из любой
локации: линк «37 ms RTD (18.5 ms в одну сторону)» — «из AWS Tokyo можно пинговать private IP okx'a
за 18.5 ms, а за 19.0 ms вдуть команду им в matching engine». Итог: «OKX стал ближе ко всем локациям
аж на 2 ms» — «реально tier1».

Развязка (alko-trading#1655): okx объявляет переезд в aws tokyo «без downtime» — «Как это бляха вообще
можно сделать, как перенести стакан за 20 ms?» (механика не раскрыта — (→ «Открытые вопросы»)).
Состоялось (alko-trading#1675): «маркет-дата стала поступать стабильнее», «но дольше на 1 мс ахаха»;
порог <19 ms был про HK-эпоху — (→ секция «E2E как бизнес-метрика» выше).

Тот же удар по alko (alko-trading#1714): «bybit переезжает из aws-singapore в aws-tokyo. А я только
что подписал контракт на сеть в Singapore, на год». Перестройка рынка (alko-trading#1462): «дорогущие
линки hk-Tokyo, hk-Frankfurt, hk-Singapore не нужны, а линкам из Токио теперь нужно больше канал» —
«тут заработают только продавцы линков».

Бонус от okx (alko-trading#1824): два ws-endpoint'а, между которыми их оптика 68 ms (из Токио 4–5 ms,
из Франкфурта 72 ms), — подписка из Франкфурта «сразу 72 из коробки», «потому что в токио нет спуска
в ебучий IGW > EC > DXGW».

**Субмарины: гонка за чужим каналом.** Наблюдение (wlsbot02#65): арбитражи Binance→Bybit бьют по его
лимиткам с делем 29 мс, при том что он держит стабильно ~33.8 мс на данных после парсинга; Bybit —
Сингапур, Binance — Токио, пинг 31–35 мс. «Так "враг", успевает получить свои данные, распарсить их,
кинуть в меня своим ордером, и это быстрее чем я получу даже просто первый байт от Бинанса!»

Три теории источника (wlsbot02#65):

| теория | суть | оценка автора |
|---|---|---|
| 1. Роутинг крупного ордера | объём режется по биржам; из Токио «может кинуть ордер на Байбит, сделать задержку 5мс и только потом кидать на Бинанс» | «почему бы идеально не синхронизировать такие ордера?» — «Вопрос открыт» |
| 2. Задержка публичной маркет-даты binance | лаг на руку локальным ММ на колокации | «звучит на уровне шапочек из фольги. Я в это абсолютно не верю» |
| 3. Прямая оптика через субмарины («Flash Boys») | «кабель между 5 городами, проложенный СУБМАРИНАМИ по дну моря» — «Как продать 5мс за многа денях» | «Я уверен, что проблема кроется именно здесь!» |

Ставка (wlsbot02#65): «Эти 3-5мс буквально могут поменять алгоритм из убыточного в сверх-прибыльный»;
«самая база для конкурентов — найти провайдера самых актуальных данных».

Ценники аренды (wlsbot02#67 — из поста здесь только ценники, остальное — его главы):

| вариант | цена | примечание |
|---|---|---|
| своя линия у провайдера | ~2–4к$/мес | риск попасть «не в те» дата-центры — «которых десятки и в Токио и Сингапуре» |
| посредник: ретрансляция готовых данных | 8к$/мес | «у которых уже есть коннект и все настроено» |
| посредник: доступ к прямому соединению | 1.5к$/мес | «плюс две недели бесплатного пробного периода» |

При этом один из посредников отдаёт своё лучшее решение по обычным маркет-данным «в 2 раза медленнее
моих» (wlsbot02#67).
